# mfiano.lib.gfx.pixel-format : A small code-generated pixel format system

A *pixel format* here is a symbol (like `rgba8888/u8`) with:

- metadata (bpp, storage, channel count)
- an encoder function (double-float RGBA -> packed storage)
- a decoder function (packed storage -> double-float RGBA)

The packing/unpacking functions are generated by `define-pixel-format` from a compact description of lanes and swizzling.

This is intended for image pipelines that use a canonical working representation of pixels as
`(simple-array double-float (*))` in RGBA order (4 floats per pixel).

## Canonical working representation

All encoders/decoders operate on this canonical form:

- pixel formats are packed and provide a decoder to a destination pixel buffer, and an encoder from a destination pixel buffer
- destination pixel buffers are `(simple-array double-float (*))` as provided by `mfiano.lib.gfx.pixel-buffer`
- each destination pixel is 4 consecutive `double-float`s in **RGBA** order
- `index` arguments point at the start of a pixel (0, 4, 8, ...)

Alpha is just the 4th channel like everything else. If a format has fewer than 3 primary channels, missing channels decode as `0d0`. If alpha is missing, it is decoded as `1f0`.

## Public API

### Types

- `pixel-format`: set of all defined pixel formats
- `pixel-format/u8`: set of all 8bpc pixel formats
- `pixel-format/u16`: set of all 16bpc pixel formats
- `pixel-format/u24`: set of all 24bpc pixel formats
- `pixel-format/u32`: set of all 32bpc pixel formats

### Format metadata

Each pixel format symbol stores metadata on its property list:

- `(get-bpp format) => 8|16|24|32`
- `(get-storage format) => :u8|:u16|:u24|:u32`
- `(get-channel-count format) => 1..4`
- `(get-encoder format) => function`
- `(get-decoder format) => function`

### Defining a format

```lisp
(define-pixel-format name
  :bpp 32
  :endianness :le
  :lanes ((8 0) (8 8) (8 16) (8 24))
  :swizzle (0 1 2 3)
  :storage :u8
  :encoder encode-name
  :decoder decode-name)
```

Parameters:

* `:bpp`: bits per pixel (8/16/24/32)
* `:endianness`: `:le` or `:be` (matters for multi-byte storage layouts)
* `:lanes`: list of `(bits shift)` specs describing packed lanes inside the pixel value
* `:swizzle`: maps lane order to canonical RGBA channel indices (0..3)
* `:storage`: how the packed pixels are stored (`:u8`, `:u16`, `:u24`, `:u32`)
* `:encoder` / `:decoder`: names of generated functions

Encoders quantize `double-float` channels in `[0,1]` to integer lane values using rounding.

## Built-in formats

### 32bpp RGBA / ABGR

* `rgba8888/u8`: bytes in little-endian order, lane order RGBA
* `rgba8888/u32`: packed `(unsigned-byte 32)`, lane order RGBA
* `abgr8888/u8`: bytes in little-endian order, lane order ABGR (swizzled to RGBA for destination pixel buffer)
* `abgr8888/u32`: packed `(unsigned-byte 32)`, lane order ABGR (swizzled to RGBA for destination pixel buffer)

### 24bpp RGB / BGR

* `rgb888/u8`: 3 bytes, RGB
* `bgr888/u8`: 3 bytes, BGR (swizzled to RGB for destination pixel buffer)

### 16-bit gray + alpha

* `ga1616/u16`: two 16-bit lanes: gray + alpha
* `ga1616/u32`: same concept, stored packed into a `(unsigned-byte 32)` (endianness matters)

In GA formats, gray decodes into `channel0` (R), and alpha decodes into `channel3` (A) within the `mfiano.lib.gfx.pixel-buffer` destination buffer. Other channels decode as `0d0`.

## Example

Decode a packed `rgba8888/u8` octet buffer into canonical `double-float` RGBA:

```lisp
(let ((packed (make-array 4 :element-type '(unsigned-byte 8) :initial-contents '(255 128 32 8)))
      (dest (make-array 4 :element-type 'double-float :initial-element 0d0)))
  (mfiano.lib.gfx.pixel-format:decode-rgba8888/u8 packed 0 dest 0 1)
  dest)
;; => #(1.0d0 0.5019607843d0 0.1254901960d0 0.0313725490d0)
```

Round-trip encode:

```lisp
(let ((packed (make-array 4 :element-type '(unsigned-byte 8) :initial-contents '(255 128 32 8)))
      (dest (make-array 4 :element-type 'double-float :initial-element 0d0)))
  (pf:decode-rgba8888/u8 packed 0 dest 0 1)
  (pf:encode-rgba8888/u8 dest 0 packed 0 1)
  packed)
;; => #(255 128 32 8)
```

## Notes / design intent

* This is built for speed and "no surprises" layout.
* `define-pixel-format` validates lane geometry (no overruns, correct swizzle size, etc.) at macroexpansion time.
* Pixel formats are symbols by design, so other systems can use them as identifiers without carrying structs around.
