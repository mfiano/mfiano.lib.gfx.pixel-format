# mfiano.lib.gfx.pixel-format : A small code-generated pixel format system

A *pixel format* here is a symbol (like `rgba8888/u8`) with:

- metadata (layout, storage, channel count)
- an encoder function (`double-float` 4-channel -> encoded storage)
- a decoder function (encoded storage -> `double-float` 4-channel)

The encoding/decoding functions are generated by `define-pixel-format` from a compact description of layout and swizzling.

This is intended for image pipelines that use a canonical working representation of pixels as
`(simple-array double-float (*))` with 4 floats per pixel.

## Canonical working representation

All encoders/decoders operate on this canonical form:

- pixel formats provide a decoder to a destination pixel buffer, and an encoder from a destination pixel buffer
- destination pixel buffers are `(simple-array double-float (*))` as provided by `mfiano.lib.gfx.pixel-buffer`
- each destination pixel is 4 consecutive `double-float`s in channel order `0..3` (typically RGBA)
- `index` arguments point at the start of a pixel (0, 4, 8, ...)

If a format has fewer than 3 primary channels, missing channels decode as `0d0`. If channel 3 (alpha) is missing, it is decoded as `1d0`.

## Public API

### Types

- `pixel-format`: set of all defined pixel formats
- `pixel-format/u8`: set of all `:u8` pixel formats
- `pixel-format/u16`: set of all `:u16` pixel formats
- `pixel-format/u32`: set of all `:u32` pixel formats
- `pixel-format/f32`: set of all `:f32` pixel formats
- `pixel-format/f64`: set of all `:f64` pixel formats

### Format metadata

Each pixel format symbol has various accessor functions:

- `(layout format) => :packed|:unpacked`
- `(storage format) => :u8|:u16|:u32|:f32|:f64`
- `(channel-count format) => 1..4`
- `(encoder format) => function`
- `(decoder format) => function`

### Defining a format

```lisp
(define-pixel-format name
  :layout :unpacked
  :storage :u8
  :channels 4
  :swizzle (0 1 2 3)
  :encoder encode-name
  :decoder decode-name)
```

Parameters:

* `:layout`: `:unpacked` (one word per channel) or `:packed` (one word per pixel)
* `:storage`: how the pixels are stored (`:u8`, `:u16`, `:u32`, `:f32`, `:f64`)
* `:channels`: number of encoded channels (1..4)
* `:swizzle`: maps encoded channel order to canonical channel indices (0..3)
* `:encoder` / `:decoder`: names of generated functions

Encoders quantize `double-float` channels in `[0,1]` to integer values using rounding for integer storage formats (`:u8`, `:u16`, `:u32`).

## Built-in formats

### 32bpp RGBA / ABGR

* `rgba8888/u8`: unpacked octets, RGBA channel order
* `abgr8888/u8`: unpacked octets, ABGR channel order
* `rgba8888/u32`: packed `(unsigned-byte 32)`, RGBA channel order (swizzled to RGBA for the destination pixel buffer)
* `abgr8888/u32`: packed `(unsigned-byte 32)`, ABGR channel order (swizzled to RGBA for the destination pixel buffer)

### 24bpp RGB / BGR

* `rgb888/u8`: 3 octets, RGB channel order
* `bgr888/u8`: 3 octets, BGR channel order (swizzled to RGB for the destination pixel buffer)

### 16-bit gray + alpha

* `ga1616/u16`: two unpacked 16-bit channels: gray + alpha
* `ga1616/u32`: two packed 16-bit channels in a `(unsigned-byte 32)` word

### Unpacked floating-point

* `:rgba/f32`: 4 unpacked `single-float`s, RGBA channel order
* `:abgr/f32`: 4 unpacked `single-float`s, ABGR channel order (swizzled to RGBA for the destination pixel buffer)
* `:rgba/f64`: 4 unpacked `double-float`s, RGBA channel order
* `:abgr/f64`: 4 unpacked `double-float`s, ABGR channel order (swizzled to RGBA for the destination pixel buffer)
* `:rgb/f32`: 3 unpacked `single-float`s, RGB channel order
* `:bgr/f32`: 3 unpacked `single-float`s, BGR channel order (swizzled to RGB for the destination pixel buffer)
* `:rgb/f64`: 3 unpacked `double-float`s, RGB channel order
* `:bgr/f64`: 3 unpacked `double-float`s, BGR channel order (swizzled to RGB for the destination pixel buffer)

In GA formats, gray decodes into canonical channel 0, and alpha decodes into canonical channel 3. Other channels decode as `0d0`.

## Example

Decode an `rgba8888/u8` octet buffer into canonical 4-channel `double-float` pixels:

```lisp
(let ((packed (make-array 4 :element-type '(unsigned-byte 8) :initial-contents '(255 128 32 8)))
      (dest (make-array 4 :element-type 'double-float :initial-element 0d0)))
  (mfiano.lib.gfx.pixel-format:decode-rgba8888/u8 packed 0 dest 0 1)
  dest)
;; => #(1.0d0 0.5019607843d0 0.1254901960d0 0.0313725490d0)
```

Round-trip encode:

```lisp
(let ((packed (make-array 4 :element-type '(unsigned-byte 8) :initial-contents '(255 128 32 8)))
      (dest (make-array 4 :element-type 'double-float :initial-element 0d0)))
  (mfiano.lib.gfx.pixel-format:decode-rgba8888/u8 packed 0 dest 0 1)
  (mfiano.lib.gfx.pixel-format:encode-rgba8888/u8 dest 0 packed 0 1)
  packed)
;; => #(255 128 32 8)
```

## Notes / design intent

* This is built for speed and a 'no surprises' layout.
* `define-pixel-format` validates parameters (layout, storage, channels, swizzle, etc.) at macroexpansion time.
* Pixel formats are symbols by design, so other systems can use them as identifiers without carrying structs around.
